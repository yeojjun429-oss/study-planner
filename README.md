# STUDY PLANNER — 계획·실제 기록 통합 버전

Python Flask 수행평가용 소스 코드입니다. 실제 인터넷 배포는 수행하지 않았습니다.

## Windows에서 시작하기

1. ZIP을 새 폴더에 압축 해제합니다.
2. VS Code에서 `app.py`, `planner.py`, `requirements.txt`가 함께 있는 `study_planner_v5_flask` 폴더를 엽니다.
3. 상단 Terminal → New Terminal에서 다음 명령어를 한 줄씩 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

4. 브라우저에서 http://127.0.0.1:5000 으로 접속합니다.
5. 회원가입 후 **설정 → 과목 관리 → 계획 → 홈 타이머 / 진도 기록** 순서로 사용합니다.
6. 종료하려면 터미널에서 Ctrl+C. 다시 실행할 때는 마지막 실행 명령만 입력합니다.

Python 3.10 이상을 사용합니다. 실행 명령은 Python IDLE의 `>>>` 창이 아닌 VS Code 터미널에 입력합니다.

## 기능

- 계정별 계획·학습 기록 분리, 비밀번호 해시, CSRF 보호
- 목표·전체 마감일, 요일별 순공 가능 시간, 집중 시간·휴식, 복습 간격
- 과목별 1~3순위·세부 학습 목표·난이도·마감일, 교재, 메모
- 시간형 목표 또는 쪽수·문제 수·단어 수 목표
- 기본 계획 입력: 과목·날짜·할 일·예상 시간. 교재/범위/시작 시간/복습/메모는 펼쳐서 입력
- 추천 공부 플랜: 날짜별 추천을 미리 확인한 뒤 빈 시간에 추가, 미배정 시간 안내
- 계획별 수동 편집, 날짜 변경, 삭제, 완료 체크
- 서버에 시작 시각을 저장하는 과목별 타이머, 새로고침 후 계속 표시, 종료 시 날짜별 저장
- 실제 시간 및 실제 완료 번호 기록, 기록 수정/삭제
- 중복 번호는 한 번만 진도에 반영, 복습은 수량 진도에 중복 합산하지 않음
- 미완료 분량을 남은 날짜에 분할 재배분, 못 옮긴 분량은 원래 날짜에 유지
- 월간 달력, 날짜별 PDF(한글 글꼴이 설치된 환경), 모바일 하단 메뉴

## 계산 규칙 — 수행평가 설명용

`planner.py`에 계산 알고리즘을 모았습니다.

1. 과목 마감일이 빠른 순서로 배분합니다. 마감일이 같으면 1·2·3순위에 각각 가중치 3·2·1을 적용합니다. 이미 배분한 시간을 가중치로 나눈 값이 작은 과목을 먼저 배치하고, 같은 값이면 순위와 난이도로 결정합니다.
2. 시간형은 총 목표 시간에서 실제 누적 시간과 미완료 계획의 남은 예상 시간을 뺍니다.
3. 수량형은 전체 범위에서 기존 완료량·실제 완료 번호·이미 계획된 번호의 합집합을 제외합니다.
4. 요일별 공부 가능량, 기존 시간표, 휴식 시간, 한 번의 집중 시간, 자정 경계를 확인하며 계획을 나눕니다.
5. 교재 범위가 없으면 시간형으로 사용할 수 있습니다. 수량형은 한 단위당 예상 시간을 분 단위 정수로 입력합니다.
6. 복습은 과목/학습일마다 선택한 간격 후 15분씩 추가합니다. 학습 계획을 배치한 뒤 남은 시간에 배치하므로 여유가 없거나 마감일을 넘으면 미배정 안내를 표시합니다.
7. 범위가 있는 미완료 계획은 실제 완료 번호를 제외한 뒤 남은 수량 × 단위당 예상 시간으로 재배분합니다. 시간형은 상세 편집의 ‘남은 예상 시간’을 사용합니다. 공부에 쓴 시간이 예상보다 길거나 짧을 수 있어 실제 시간을 무조건 빼지 않습니다.

예: 문제 31~35번은 5문제입니다. 다음 날 34~38번을 기록하면 총 완료 범위는 31~38번, 즉 8문제입니다.

시간형 진도는 실제 누적 시간/목표 시간, 수량형 진도는 중복 없는 완료량/전체량입니다. 계획 완료 체크만으로 실제 시간이나 수량을 자동 생성하지 않습니다.

## 기록 사용 시 참고

- 시작 전 완료량은 과목 범위의 처음부터 연속으로 끝낸 수량입니다.
- 타이머 시간을 저장한 후 문제 번호만 추가하려면 실제 시간에 0분을 입력합니다.
- 단어 수는 단어장의 순번으로 기록합니다.
- 타이머는 브라우저를 닫아도 계속 흐릅니다. 종료 시 저장하며, 잘못 켜 둔 기록은 진도 화면에서 수정할 수 있습니다.
- 과목 삭제는 해당 과목의 계획과 실제 기록도 삭제합니다. 계획만 삭제하면 실제 기록은 남습니다.
- 기존 코드의 로컬 데이터는 `instance/study_planner.db`에 있습니다. 기존 데이터를 이어 쓰려면 프로그램을 종료하고 해당 파일을 백업한 뒤 새 폴더의 같은 위치로 복사합니다. ZIP에는 사용자 데이터가 포함되지 않습니다.

## 테스트

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

27개 자동 검사: 마감일 우선 배분, 휴식/가능 시간/자정 경계, 기존 계획 보존, 재생성 중복 방지, 복습, 부족 시간 안내, 겹치는 수량, 부분 재배분, 페이지 렌더링, 입력 검증, 기록 수정/삭제, 타이머 중복 실행·종료·한국 시간 자정 분할, 계정 분리, CSRF 등.

테스트는 별도 임시 SQLite DB를 사용합니다. 실제 DB를 초기화하지 않습니다.

브라우저 엔진 다운로드가 실패해 실제 브라우저에서 CSS 배치·클릭 동작을 확인하지 못했습니다. 자동 검사는 Flask 요청/응답과 계산·저장 동작을 확인한 것입니다. 실제 PostgreSQL 연결 및 인터넷 배포 검사는 아직 하지 않았습니다.

## Render + 외부 PostgreSQL 배포 준비

`render.yaml`에는 Render `plan: free` 웹 서비스만 정의되어 있습니다. 유료 DB 자동 생성 항목은 없습니다. `DATABASE_URL`은 외부 PostgreSQL의 연결 문자열을 직접 입력하도록 설정되어 있습니다.

- `SECRET_KEY`: Render에서 생성하는 비밀키
- `DATABASE_URL`: 외부 PostgreSQL 제공자의 연결 문자열. 제공자가 요구하는 SSL 설정을 포함합니다.
- `COOKIE_SECURE=1`: HTTPS 배포용
- `postgres://` 또는 `postgresql://` 주소는 설치된 psycopg 3 드라이버에 맞게 변환합니다.
- 로컬은 SQLite, 배포는 PostgreSQL을 사용합니다.
- 기존 Render Blueprint를 갱신할 때 새 `sync: false` 환경 변수는 대시보드에서 수동으로 설정해야 합니다.
- 무료 제공 조건과 DB 이용 가능 여부는 실제 배포 시 확인해야 합니다.

공식 설정 참고: https://render.com/docs/blueprint-spec

## 파일 구조

- `app.py`: 회원 인증, DB 읽기/저장, 페이지와 폼 요청 처리
- `planner.py`: 범위 계산, 진도, 자동 계획, 재배분
- `templates/`: HTML 화면과 공통 입력 폼
- `static/`: 스타일, 타이머 표시, 진도 방식별 입력란 전환
- `tests/test_planner.py`: 자동 검사
- `render.yaml`, `Procfile`: 배포 설정

## 휴대폰에 설치하는 웹 앱

브라우저가 공통 HTML의 manifest 링크를 읽으면 앱 이름, 아이콘, 시작 주소와 화면 표시 방식을 확인할 수 있습니다. 다른 학생은 HTTPS 배포 주소를 열어 홈 화면에 설치한 뒤 회원가입할 수 있습니다. 로그인과 기록 저장에는 서버 연결이 필요합니다.

manifest는 JSON 형식이므로 주석 대신 여기서 각 항목을 설명합니다.

- `id`: 브라우저가 같은 앱인지 식별하는 경로입니다.
- `name`, `short_name`, `lang`: 앱의 이름, 홈 화면에서 쓸 짧은 이름, 표시 언어입니다.
- `start_url`, `scope`: 앱을 열 때 접속할 경로와 앱 내부로 취급할 경로의 범위입니다.
- `display`: 독립된 앱 창 형태로 표시합니다.
- `theme_color`, `background_color`: 브라우저 UI와 시작 화면에 사용할 색입니다.
- `icons`: 아이콘 파일 주소, 픽셀 크기, 파일 형식입니다.
